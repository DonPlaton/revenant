How Revenant brings a workspace back

FOUR STEPS
01

The machine dies

Nine agent sessions across nine directories go down with the terminal. Each one holds hours of context you would rather not retype.

02

Transcripts outlive the crash

The registry of running sessions is wiped on the next start. The conversation files are not, so they are what Revenant reads.

sessions/<pid>.json projects/<slug>/<id>.jsonl history.jsonl
03

You pick a window

Drag the caret from six hours to ninety days. Sessions hang off the time axis, newest first, each with the last thing you said to it.

1hcheckout-web
4hml-pipeline
04

Revive

One tab per session in Windows Terminal, iTerm2, GNOME Terminal, tmux or whatever else you use, already in the right folder and resumed.

What it reads Three files per agent. Nothing is ever written back.
sessions/*.json

One file per running session. Cross-checked against the real process, so a recycled pid cannot pose as a live one.

PRUNED ON STARTUP
projects/*/*.jsonl

The conversations. Directory, branch and version come from the first records of each file. Codex files the same thing by date.
